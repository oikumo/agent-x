## 2. Root-cause findings (why check showed 10 errors, not v1's claimed 1)

`main()` runs projections (incl. `splice_config`, which SystemExits on missing jsonc markers)
BEFORE `run_all_checks` ⇒ at v1 pause every check error was masked by the jsonc exit. With
markers in place, 10 latent errors surfaced, in 3 classes:

**A. PARSER BUG (harnessc.py L161) — the big one.** The record regex
`r"@([a-z]+)\s+(\S+)\s*(.*)$"` eats the space before `:` in ATTR-LESS records
(`@var x : 123`, `@pred p : path_in(...)`). `split_payload` needs `" : "`; rest starts at `:`,
never matches at i=0 ⇒ payload="" and the tokens fall into shlex ⇒ "not k=v" parse errors that
go to a THROWAWAY list (main L569: `parse(text, [])` — silently dropped!). Consequences:
all 19 @var values empty in the IR (g.nav `paths` etc. would resolve to `""`), all 8 @pred
payloads empty (⇒ the 8 "pred vocab" errors).
FIX (the ONE harnessc.py edit this cycle — drop `\s*` so rest keeps its leading space;
shlex tolerates it; `split_payload` finds `" : "` at i=0):
```
OLD (L161): m = re.match(r"@([a-z]+)\s+(\S+)\s*(.*)$", line)
NEW:        m = re.match(r"@([a-z]+)\s+(\S+)(.*)$", line)
```

**B. .omt L129:** `see=@doc.err.v2m` unresolved — no such @doc exists.
FIX: `see=@msg.err_v2m` (exists, L132).

**C. .omt L134:** payload `Abstract Partner not ABC+@abstractmethod — BLOCK` — REF_RE parses
`@abstractmethod` as a bare kind ref. FIX (data-side, chosen): drop the `@` →
`Abstract Partner not ABC+abstractmethod — BLOCK` (mirrors mvc_check.py L140-141 text).
OPTIONAL later cycle (code-side, principled): REF_RE (L71; used ONLY by check_refs — verified)
gains a prefix class so `@` must follow start / whitespace / `=` / `(` / `,`:
`(?:^|[\s=(,])@([a-z]...` — capture-group indices unchanged (non-capturing prefix). NOT this
cycle: non-contiguous with the L161 fix ⇒ would burn a second receipt cycle. Checked: no
payload legitimately needs mid-token `@` (only `glob|@var` in @pred path_in — kind-level
mention, unharmed).
