## Summary (one line)

**A standalone React+TypeScript web app in this repo (but independent of agentx and its runtime) for visually creating, simulating, and analyzing weighted P/T Petri nets — powered by a TypeScript port of the shipped `agentx.model.petri_net` engine semantics — plus a versioned JSON import/export format defined once in `shared/petri-net/` and implemented by both the tool and (as a follow-up feature) the Python library.**

## Purpose

### What this project is

Three deliverables, developed as separate harness features under this project home:

1. **The shared JSON format** (`shared/petri-net/`) — the contract. `FORMAT.md` (spec), `petri-net-json-v1.schema.json` (JSON Schema), canonical-serialization rules, example nets, and later **conformance vectors** (`{net, expected analysis results}` JSON generated by the tested Python library, consumed by the TS test suite — so "shared format" means *shared semantics*, not just shared schema).
2. **Petri Net Studio** (`tools/petri-net-studio/`) — the independent web app: visual editor (places/transitions/weighted arcs/tokens), click-to-fire simulation with enabled-transition highlighting, analysis dashboard, reachability-graph explorer, JSON import/export. React + TypeScript + Vite + React Flow (D2); **pure browser, no backend** (D1) — the engine is a TS port of the library; deployable as static files.
3. **The agentx-side io module** (`src/agentx/model/petri_net/io.py`) — the ONLY `src/`-touching piece: `net_to_json` / `net_from_json` + validation, implementing the same format so agentx (and later feature_001) can exchange nets with the tool. Fulfills the library's deferred v2 "JSON export" backlog item (petri_net_library PROJECT.md "Out of scope: DOT/JSON"). One small harness-tracked feature.

### What this project is **not**

- **Not coupled to agentx at runtime.** The tool never imports agentx code, never calls a Python backend, never touches the harness. Independence is a *runtime* property (D1); *process* follows the harness (project home + features — D4).
- **Not a modification of the shipped library.** `model.py`/`analysis.py`/`errors.py`/`coverability.py` stay untouched; `io.py` is purely additive.
- **Not feature_001.** feature_001 (session user objectives) remains a separate future consumer of the library; this project's format merely gives it a serialization option.
- **Not a new semantics.** The TS engine must reproduce the library's exact semantics (weighted firing, canonical ordering, completeness-explicit results, `max_states` limits) — verified via conformance vectors (D8), not by re-invention.
- **Not a server/multi-user/colored-net/timed-net tool.** Pure client-side; colored/timed/hierarchy extensions are out (the format's `version` field future-proofs them).
- **Not a simulator engine beyond the model layer.** Interactive click-to-fire only (the library's `simulator.py` is itself deferred v2).

### Requirement anchor

- **Semantics anchor:** the shipped, tested library — `src/agentx/model/petri_net/{model,analysis,errors}.py` (99 tests) — plus its requirement doc `.meta/doc/petri_nets/petri_net_python_coding_agents.md`. The TS port is a *port*, with the Python library as the executable specification.
- **Project origin:** user request 2026-08-23 ("ui tool that use[s] the library to create petri nets, execute analysis and create a json format to import and export it … modern html ui … typescript with a modern web framework … independent of agentx and meta harness, but must share the same import export file format. same repo" + "project in meta harness, to develop after defining it, as a feature(s)").

### Recurring principles (invariants the project preserves)

- **No-overclaim UI** — the library's signature semantics (`value: True/False/None`, `complete`, `reason`, required `max_states`) become a first-class UI language: every verdict carries a ✅ proven / ❌ disproven / ❓ unknown badge, truncation reasons are shown verbatim, and `max_states` is a visible user control, never a hidden constant.
- **Format is the contract** — one spec, one schema, versioned from day one; both implementations validate against it; canonical (sorted, deterministic) serialization for git-friendly diffs (mirrors library D6).
- **Independence by construction** — `tools/petri-net-studio/` has its own toolchain (npm/Vite/Vitest) and builds and tests with zero agentx/harness imports; the only shared directory is `shared/petri-net/`.
- **Conformance over hope** — the TS port earns trust by passing golden vectors generated by the 99-test Python library (D8), including "unknown"/truncated cases.

## Vision + standing principle + main objectives

**Standing principle (non-negotiable): the tool inherits the library's epistemics — proven / disproven / unknown are distinct and visible.** A Petri-net tool that silently truncates state-space exploration and reports "deadlock-free" is worse than no tool. The Studio's analysis UI is built around `complete`/`reason`/`max_states`, not around bare booleans.

**Main objectives:**

- **(a) A versioned, deterministic JSON format for weighted P/T nets** — minimal structural core (places/transitions/weighted arcs/initial tokens), optional UI-namespaced `layout`, stricter-than-library naming (unique across places ∪ transitions, D6), canonical serialization. Success = spec + schema + examples; both implementations round-trip to identical canonical bytes.
- **(b) A genuinely useful visual workbench** — draw a net in minutes, fire transitions by click, run analyses with honest verdicts, explore the reachability graph, save/load/share as JSON. Success = the phased feature roadmap below ships and the app builds as static files.
- **(c) A trustworthy TS engine** — semantic equivalence with the Python library demonstrated mechanically by the conformance suite, including exact-rational invariants (fraction arithmetic in TS) and truncated-search "unknown" cases.

**What is NOT the vision:** not a research state-space optimizer; not a general graph editor; not a replacement for the library; not an agentx UI screen.

## Decisions log (LOCKED v1.1 — do not re-litigate without new evidence; changes require an explicit re-lock entry in the iteration log)

- **D1 — Architecture: pure browser, TS engine port (LOCKED by user Q&A 2026-08-23).** No backend; the engine is a TypeScript port of the Python library; static-file deployable. Alternatives rejected by user: FastAPI backend (couples to agentx, needs a server), Pyodide (real library in WASM — heavy payload, slow start). Consequence: two engines exist ⇒ D8 conformance suite is mandatory.
- **D2 — Frontend stack: React + TypeScript + Vite + React Flow (xyflow); Vitest; Zustand (LOCKED by user Q&A 2026-08-23).** React Flow is purpose-built for node-graph editors; reachability graph viz uses cytoscape.js/elkjs auto-layout (feature 5). Alternatives considered: Svelte/SvelteFlow, Vue/Vue Flow.
- **D3 — agentx-side `io.py` IS part of the plan, as a follow-up harness feature (LOCKED by user Q&A 2026-08-23).** Only `src/`-touching feature (roadmap #2); fulfills the petri_net_library deferred "DOT/JSON export" v2 backlog item (JSON half).
- **D4 — Process follows the meta harness; runtime does not (user directive 2026-08-23: "project in meta harness, to develop after defining it, as a feature(s)").** Project home + scaffolded features + phase pipeline for development; the shipped tool artifact has zero agentx/harness dependencies. "Independent of agentx and meta harness" = runtime/deployment independence.
- **D5 — The format is the ONLY coupling.** `shared/petri-net/` holds FORMAT.md + JSON Schema + examples + conformance vectors; both implementations validate against the schema; nothing else is shared (no code imports across the boundary).
- **D6 — Format is stricter than the library.** Names unique across places ∪ transitions (the model permits ambiguity; the format forbids it); weights positive ints; tokens non-negative ints; `format`+`version` mandatory; `layout` optional and UI-namespaced (Python ignores it); initial marking only in v1.
- **D7 — Canonical serialization.** Sorted arrays by name, explicit weights, stable key order ⇒ byte-identical output for identical nets; git-friendly diffs; round-trip equality is a tested property of BOTH implementations.
- **D8 — Conformance vectors.** Golden `{net, expected}` JSON files generated by a script against the tested Python library (feature 2 provides the generator), executed by Vitest against the TS engine (feature 5 wires the runner); must include truncated/`complete=false`/"unknown" cases per the library's per-function test matrix tradition. **(Amended by re-lock — iter 7, 2026-08-23: feature 2 shipped without the generator; the generator deliverable moved to feature 4 — runner wiring stays feature 5.)**
- **D9 — Feature decomposition per the roadmap table; feature numbers auto-assigned by `new_feature.py` at scaffold time (never hard-coded in docs).** Features 1–2 are minor_feature (declaration-only artifacts); 3–5 are major_feature (design doc + TDD pipeline applies).
- **D10 — No-overclaim UI is a signature feature, not polish.** Every analysis verdict renders `value`/`complete`/`reason`; `max_states` is a user-visible dial; truncated results are visually distinct from proven ones.
