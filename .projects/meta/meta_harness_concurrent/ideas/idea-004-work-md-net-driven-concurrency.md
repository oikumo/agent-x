## 1. Problem Statement

The current `WORK.md` (repo root) is a **flat, manual task list** that:
- Does not reflect the **net-of-nets state** (supervisor + per-project/per-feature subnets)
- Cannot represent **resource capacities** (`agent_attention`=1, `src_edit_capacity`, `tests_capacity`, `harness_surface_round`, `e2e_receipt`) structurally
- Has **no mechanical link** to the `META_NET.petri.json` + `net_state.sidecar.json` authority files
- Requires **manual reconciliation** between task status and net marking — drift is silent
- Cannot **block** invalid transitions (e.g., starting a feature when `agent_attention` token is held, or editing harness surface without receipt)

The meta harness needs a **WORK.md that is a live projection of the net state**, where:
- Task checkboxes map to **place markings** in the supervisor/subnet net
- Resource conflicts are **structurally visible** (deadlocks = blocked tasks)
- The agent's **single-threaded execution** (`agent_attention`=1) is modeled, not assumed
- `omt_net_sync` keeps WORK.md and net state **deterministically aligned**

---

## 2. Resolution: WORK.md as Net Projection + Agent Control Surface

### 2.1 Core Principle

> **WORK.md is a human-readable projection of the net's live marking + a controlled mutation surface for the agent.**
> - Read path: `omt_net_sync` (or `omt_net{op:probe}`) → render WORK.md from net state
> - Write path: Agent edits WORK.md checkboxes → `omt_net_sync` proposes splice/fire → analyzer validates → net commits

This makes WORK.md **both a view and a control surface**, with the net as the authority (IDEA-001 D5, IDEA-003 D1).

### 2.2 Two-Source-of-Truth Pattern Extended

| Source | Authority | Role |
|---|---|---|
| `META_HARNESS.omt` + phase FSM + ledger | **Primary** — workflow driver, gate enforcement | Controls `omt_phase`/`omt_complete`/`omt_tdd` |
| `META_NET.petri.json` + `net_state.sidecar.json` | **Secondary** — concurrency model, conflict detection | Controls `omt_net_fire`/`omt_net_splice`; blocks invalid fires |
| **WORK.md (this proposal)** | **Projection + Mutation Surface** — human-readable net state; agent edits propose net mutations | `omt_net_sync` keeps projection ↔ net deterministic |

**Reconciliation:** `omt_net_sync` runs at every `omt_complete` exit (mirroring drift check) and on explicit `omt_net{op:sync}`. If WORK.md checkboxes diverge from net marking → LOG drift, surface to agent, do NOT auto-resolve.

## 4. Synchronization Protocol: `omt_net_sync`

### 4.1 Trigger Points

| Trigger | Direction | Operation |
|---|---|---|
| `omt_complete` exit | Net → WORK.md | `omt_net_sync` renders WORK.md from net state |
| `omt_phase` advance | Net → WORK.md | `omt_net_sync` updates phase places |
| `omt_tdd` cycle step | Net → WORK.md | `omt_net_sync` updates TDD places |
| `omt_net_fire` / `omt_net_splice` | Net → WORK.md | `omt_net_sync` incremental update |
| Agent edits WORK.md checkboxes | WORK.md → Net | `omt_net_sync --propose` → splice/fire proposal → analyzer validates → commit |

### 4.2 Sync Algorithm (Deterministic)

```python
def omt_net_sync(direction: "net_to_md" | "md_to_net_propose"):
    # 1. Load net file + sidecar (authority)
    net, marking = load_net_with_sidecar()
    
    if direction == "net_to_md":
        # 2. Render WORK.md from marking (deterministic template)
        md = render_work_md_from_marking(net, marking)
        write_if_changed("WORK.md", md)
        
    elif direction == "md_to_net_propose":
        # 2. Parse checkboxes from WORK.md
        desired_marking = parse_work_md_checkboxes(read("WORK.md"))
        
        # 3. Compute diff: desired vs actual marking
        diff = compute_marking_diff(marking, desired_marking)
        
        # 4. Propose fires/splices to achieve desired (minimal set)
        proposals = propose_fires_for_diff(net, marking, diff)
        
        # 5. Validate each proposal via analyzer (blocking)
        for prop in proposals:
            if not analyzer.is_enabled_at(net, prop.transition, marking):
                log_drift("proposal_blocked", prop, marking)
                return SyncResult(blocked=True, proposals=proposals)
            
        # 6. Return proposals for agent to confirm + fire via omt_net_fire
        return SyncResult(proposals=proposals)
```

### 4.3 Conflict Resolution Rules

| Conflict Type | Net Detection | Resolution |
|---|---|---|
| `agent_attention` double-booked | Place invariant violation (token > 1) | `omt_net_invariant` blocks second fire; WORK.md shows `[!]` on both |
| Harness edit without receipt | `harness_surface_round` token=0 | `omt_net_fire` for harness edit transition disabled |
| Phase advance without gate | Phase transition not enabled in net | `omt_phase` still works (primary), but net logs drift |
| Subnet dependency violated | Boundary port `feature_ready`=0 | `omt_net_fire` for `phase:Programming` disabled |

## 8. Honest Limits

- **Still single-threaded**: `agent_attention`=1 means the agent executes serially. The net models concurrency for **visibility and conflict detection**, not parallel execution.
- **Two sources of truth persist**: WORK.md (human) + net (machine). `omt_net_sync` is the **only** reconciliation mechanism. No silent auto-fix.
- **Human edits are proposals**: Agent edits WORK.md → `omt_net_sync --propose` → analyzer validates → agent confirms → `omt_net_fire`. Human cannot bypass net authority.
- **Format stability**: WORK.md template changes require net schema version bump + conformance vector regeneration.
